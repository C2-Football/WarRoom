## Duplicate checkout and recovery

Actual `71d8971` checkout handler, executed with isolated provider/database dependencies: two identical POSTs returned `[200,200]` and created **two** checkout sessions. The stable customer key did not protect the checkout itself.

The repair retains one private durable attempt per account/product with a fixed Stripe idempotency key and exact request. Repeated or competing requests reuse the recorded session; lost responses and rejected database checkpoints recover the same key. Current session retrieval follows idempotent creation because Stripe can replay the original stale `open` response. Plan/return changes expire a verified old open link before replacement; completed checkout or an existing nonterminal same-product subscription returns truthful HTTP 409 recovery. Legacy product identity is checked from subscription/session metadata or configured provider price IDs. Unknown legacy prices/history fail closed. Existing prices, seven-day DHQ trial and different-product purchases remain unchanged.

Provider idempotency retention is finite. After 23 hours, a missing session checkpoint uses paginated customer history and the exact attempt metadata; no match cannot justify creating another charge. Such an unknown attempt remains an explicit support/reconciliation dependency. [Stripe idempotency](https://docs.stripe.com/api/idempotent_requests), [session history](https://docs.stripe.com/api/checkout/sessions/list)

Root independent review found a stale-worker race in the first 60-second lease: worker A could resume after worker B replaced its lease, rotated the plan, and created a new link, then expire B’s link before its stale database checkpoint failed. The actual delayed-provider regression reproduced it. The lease is now seven minutes, exceeding the documented 400-second hosted worker limit; at 61 seconds a second request remains blocked and cannot rotate the attempt. Database nonce checks additionally reject stale checkpoints. [Supabase limits](https://supabase.com/docs/guides/functions/limits)

Migration `20260920050000` is additive and replayable. Checkout records/RPCs are service-only; claim/checkpoint order is gate, account, attempt. Deletion cannot be certified by a missing `session_id`: an uncertain external create may have succeeded. The native deletion lane is extending its inventory and cleanup to include attempts and older open links before account removal. This compatibility batch must accompany checkout release.

## Transfer and native restore

Actual provider documentation establishes that `TRANSFER` has from/to ID arrays, with optional store/environment, **without purchase IDs**, and is sent only to the destination. Different configured restore modes can transfer, retain, or alias identities. Source setup documentation does not establish the selected mode. [Transfer fields](https://www.revenuecat.com/docs/integrations/webhooks/event-types-and-fields), [restore behavior](https://www.revenuecat.com/docs/projects/restore-behavior)

The prior handler treated this shape as an unknown subscriber and acknowledged it. It now returns 503 explicitly after authenticating/validating a transfer, performs no ownership mutation, and logs the event ID for recovery. This preserves delivery retry and known prior access; **it does not implement transfer fulfillment**. The remaining implementation needs current provider ownership reads, unique app-account mapping, exact affected purchases, transactional reassignment/recalculation with independent stores/gifts preserved, deduplication, concurrent transfer/event checks and legacy bootstrap. REST v2 can search current subscriptions by any associated store subscription identifier. [RevenueCat subscription API](https://www.revenuecat.com/docs/api-v2/subscription)

Release remains held until provider read access/project identity and current restore behavior can be verified and that path is implemented/tested. Missing access is a consolidated external prerequisite, not permission to revoke guessed sources, grant guessed access or acknowledge an unfulfilled restore.
