## Prioritized baseline issues / reproduction leads

### INV-01 — High: private local planning and provider credentials survive account switch

Reproduced with the exact baseline `js/core.js` logout function and `js/shared/empire-decisions.js` in a VM with isolated fake browser storage. Account A tracked a private trade plan and note; logout removed only the three auth tokens; after setting account B session, `EmpireDecisions.list()` returned A's title and note. `mfl_api_key` and `espn_s2` also remained in sessionStorage. No real data read or changed.

Root cause: global `empire_decisions_v1`; unscoped DhqStorage; logout `js/core.js:153–163` clears only `od_auth_v1`, `fw_session_v1`, `od_session_v1`. Commissioner tasks/prefs are global and treasury is league-only. Security agent independently owns account-scoping correction; coordinate Empire/logout in the same boundary fix. Verify two identities, logout/back/reopen, same account recovery, preserved unknown-owner legacy records, provider secrets removed, and no broad destructive storage purge.

### INV-02 — High: a typo in Sleeper username strands the primary connection journey

Source reproduction path: fresh account → Add a league → submit invalid username. `js/app.js:1576–1577` persists any nonempty string and reloads before validating it. `loadSleeperData` then reports username failure at 514–518. Subsequent UI (`1574–1588`) offers editable input only if there is no stored username; otherwise it shows LeagueSelector/error without a change/reconnect action. Hub can misleadingly report zero connected leagues while the error remains inside Add a league. Browser reproduction and a correction are assigned to inventory agent next.

Expected: username lookup validates before durable connection change; busy/duplicate-submit behavior; explicit invalid-user/provider failure; input remains usable; reload success uses the validated identity; change connection does not corrupt email session.

### INV-03 — High where private decisions matter: silent failed local saves

Isolated VM reproduction: make `App.DhqStorage.set` return `false` (actual wrapper's quota behavior). `EmpireDecisions.track({title:'Unsaved because storage full'})` returns a success-shaped object but immediate list is empty. `write()` ignores both false and thrown storage failures; Commissioner modules show similar best-effort patterns. This does not prove a normal browser currently has full storage, but it proves a required failure path loses work without truthful feedback. Root/security coordinate scoped persistence and error propagation; UI must keep draft/retry available, then verify reload after successful save.

### INV-04 — High reproduction lead: initial provider detail failure becomes a false empty portfolio

`loadSleeperData` (`js/app.js:508–568`) clears previous leagues, catches each league roster/user fetch individually, logs it, and finally finishes loading without recording a user-facing failed-league count or retry. If the league list succeeds but all detail requests fail, hub displays zero connected leagues and Add a league displays `No leagues found for 2026`. If only some fail, Empire's denominator silently omits those known connected leagues. Reproduce with browser-intercepted roster failure and partial failure, then require explicit incomplete coverage/retry and stale-good preservation. Do not fix by filling invented empty rosters or scores.

### INV-05 — Context/navigation lead: historical league deep links have no season recovery

`selectedYear` is hardcoded `2026` (`js/app.js:299`); `AVAILABLE_YEARS` is declared but `setSelectedYear` has no call sites. Route parser accepts league/tab but no season. Historical league URL not in 2026 list is silently left at hub after initial route attempt; user has no visible season switch. The Wire may intentionally handle history separately, so verify the intended deep-link contract before changing year navigation. Do not claim all historical routes work based on current-year tests.
